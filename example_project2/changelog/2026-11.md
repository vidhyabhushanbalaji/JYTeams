# Changelog — November 2026

Released as `1.8.0` on 2026-11-06, with `1.8.1` following on 2026-11-12.

## 1.8.1 — 2026-11-12

### Fixed
- Placement walk no longer opens the same folder twice when two child descriptions both match,
  which previously inflated `folders_visited` and occasionally duplicated candidates.
- `meridian add --new-folder` now creates the new directory under the highest-ranked candidate
  instead of always under the previous selection.
- Webhook signature verification rejected bodies containing non-ASCII characters because it
  hashed the parsed JSON rather than the raw body. Verification now uses raw bytes.

### Changed
- `MERIDIAN_PLACEMENT_STEP_BUDGET` default raised from 16 to 24 after the median tree depth in
  production came in higher than estimated.

## 1.8.0 — 2026-11-06

### Added
- **Project deletion.** `DELETE /api/projects/{id}` removes rows, then blobs that no other
  project references. Shared blobs are retained; see [ADR 0002](../decisions/0002-content-addressed-blob-storage.md).
- **`meridian audit export`** for exporting audit rows by actor or date range, as `ndjson`.
- **`folders_visited` and `fallback_used`** in search responses, so clients can present honest
  cost metadata instead of guessing.
- **`GET /.well-known/meridian-jwks.json`** as a stable, cacheable path. The previous path still
  responds for one release.

### Changed
- Search ranking now runs in a single consolidation call, batched by `MERIDIAN_SEARCH_RANK_BATCH`
  when the log is large. Relevance values within one response are comparable; across responses
  they are not, and the documentation now says so explicitly.
- Import validation rejects archive entries whose normalised path escapes the upload root,
  instead of stripping the traversal prefix and continuing.

### Deprecated
- `GET /api/search` (query string form) is deprecated in favour of `POST /api/search`. It will
  be removed in `2.0`.

### Fixed
- A failed folder description no longer blocks its ancestors from being described; the parent is
  written with the child marked `failed` and `meridian reindex --failed` retries just that node.
- Job leases are released on graceful shutdown rather than waiting for the five-minute expiry,
  so a rolling deploy no longer stalls the queue.
- `meridian tree --depth 0` now prints only the root instead of the entire tree.

## Upgrade Notes

- No schema changes in `1.8.1`; `1.8.0` adds `audit_events` and an index on
  `directories(project_id, path)`. Both apply automatically on boot.
- If you pinned `MERIDIAN_PLACEMENT_STEP_BUDGET`, review it — the new default is higher and the
  old value will prune deeper trees earlier than intended.

## Known Issues

- Renaming a folder still requires `meridian tree move`, which re-describes the whole subtree.
  UI support is tracked in the [roadmap](../product/roadmap.md).
- The fallback sweep can be slow on trees near the 40-document threshold; it is bounded by
  `MERIDIAN_SEARCH_TIMEOUT_MS` per call, not overall.
